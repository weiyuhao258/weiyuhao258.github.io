PNDbotics Reinforcement Learning for Motion Control Internship · Jul 2026 – Oct 2026 Whole-body teleoperation and motion retargeting, general-purpose motion tracking, Transformer architecture improvements, and GPU training optimization. View details

Whole-Body Teleoperation and Motion Retargeting

To make a humanoid robot follow a human operator, I used the Mink inverse kinematics toolkit to convert human skeletal motion captured by VR devices into whole-body joint targets. This process, called motion retargeting, accounts for differences in body proportions and joint structures between humans and robots. Inverse kinematics (IK) computes joint configurations from target positions and orientations. I also resolved ordering and timing issues in asynchronous ROS 2 message processing and improved offline data collection, human-body calibration, and preprocessing tools for Pico devices.

General-Purpose Whole-Body RL Motion Tracking

To train a single control model to track diverse reference motions, I built a whole-body motion tracking pipeline with mjlab. Following Humanoid-GPT, I represented motions using Harmonic Motion Embedding (HME), grouped similar motions with K-Means, and trained a PPO expert policy for each motion cluster. I then used DAgger (Dataset Aggregation) to query the corresponding experts at states visited by the student policy and aggregate their supervision, distilling the experts into a unified motion tracking policy.

After observing that parameter transfer between similar motion clusters could accelerate convergence, I used trained models to warm-start nearby clusters. I formulated the joint selection of training order and initialization sources with CP-SAT to minimize HME transfer distances between clusters, subject to the theoretical minimum number of training batches.

Parameter Reuse and Multi-GPU Scheduling for PPO Experts

Each motion cluster contains similar motions, and its expert policy specializes in tracking them. The original pipeline trained every expert from scratch with PPO (Proximal Policy Optimization, a reinforcement learning algorithm). I explored warm starts: initializing new experts with parameters from previously trained models. In comparative experiments with the same number of training iterations, initialization from clusters closer in HME space generally achieved higher tracking success rates.

Parameter reuse also requires coordinating the training order. A model can only reuse parameters from completed models, while waiting for dependencies can leave GPUs idle. I formulated this as parallel task scheduling with dependency constraints. With the minimum number of training batches fixed, a CP-SAT constraint optimization solver jointly selects the first batch, each task's execution batch, and its initialization source, favoring sources that are close in HME space.

Problem Analysis and Modeling Details
1. Jointly Consider Parameter Reuse and GPU Parallelism

Choosing the nearest model for every task independently can produce an infeasible schedule: the source model may not have finished training, or two tasks may wait on each other. Initialization sources and execution order must therefore be planned together. A successfully trained model can initialize any number of tasks that start later; they do not need to run on the same GPU.

2. Fix the Batch Count, Then Optimize Initialization Sources

The model approximates expert training times as equal and uses synchronous batches: each batch finishes before the next begins. For N motion clusters and G GPUs, at most G tasks fit in each batch, requiring at least T = ⌈N / G⌉ batches. With 96 clusters and 8 GPUs, this gives 12 batches of 8 training tasks.

Once the batch count is fixed, the HME distance between an initialization source and a target cluster serves as a proxy for transfer difficulty. Minimizing the sum of these distances jointly optimizes which models train first, when they become available for reuse, and where later models obtain their initial parameters.

3. Solve Batch Assignments and Dependencies with CP-SAT

For each motion cluster i, an integer variable wi specifies its execution batch. A Boolean variable xij indicates whether task j is initialized from task i, and Dij is their HME distance. Tasks in the first batch train from scratch; every other task must select one completed model as its initialization source, or parent in the dependency graph. The solver also chooses which clusters enter the first batch.

Capacity constraints limit the number of tasks in each batch. Dependency constraints require initialization sources to finish in an earlier batch, ruling out circular waits. CP-SAT jointly searches over the first batch, execution batches, and dependencies, avoiding initialization choices that would prevent full GPU utilization.

4. Replan Remaining Tasks After Training Failures

The initial schedule assumes every completed task yields a usable model. If a model is discarded for poor performance, tasks that depend on it must be replanned. Tasks are partitioned into successful models S, discarded models D, and untrained tasks U. Models in S remain available, models in D are excluded, and tasks in U may initialize from S or from other tasks that finish earlier in the new schedule.

After each batch, if R tasks remain, the scheduler uses K = ⌈R / G⌉ as the upper bound on the remaining batch count and solves the assignments and dependencies again. Successful models no longer occupy GPU slots in subsequent batches and can directly initialize new tasks, preserving the value of completed training.

Transformer Policy Architecture Improvements

To jointly model the robot's state history and future motion targets, I redesigned the architecture as a two-stream temporal Actor–Critic. Robot observation history and reference motion are embedded separately, one token per frame. Causal self-attention models the state history, while cross-attention reads the target motion sequence. The history window contains 10 past frames and the current frame; the reference motion window contains 10 past target frames, the current target frame, and 10 future target frames, providing both temporal context and upcoming targets.

Two sequential Fusion Blocks combine the streams. The first updates all 11 history tokens; the second computes queries and subsequent outputs only for the current token, omitting final-stage computations that do not contribute to the output head. It still reads the full keys and values (K/V) from the 11-frame history and 21-frame reference motion, limiting computational overhead while using a longer temporal context.

Inputs, Attention-Based Fusion, and Removal of Unused Computation
Preserve Temporal Information Frame by Frame

The robot observation input is 11 × 93 for the Actor and 11 × 219 for the Critic; both use a 21 × 67 reference motion input (frames × features per frame). Reference motion specifies the target movement to track, including future targets, rather than control actions previously executed by the robot. Each stream is mapped to one token per frame, without temporal pooling.

Model State History Before Reading Reference Motion

Each Fusion Block contains causal self-attention, cross-attention, and a feed-forward network (FFN), with residual connections. Cross-attention queries (Q) come from history tokens updated by self-attention, while K/V come from reference motion tokens. Rotary positional embeddings (RoPE) are applied to Q and K. Both blocks receive the same reference motion embeddings, but have separate normalization and projection parameters.

Remove Only Computations Unused by the Output Head

Fusion Block 1 retains outputs for all history tokens. Fusion Block 2 computes self-attention queries, cross-attention queries, and FFN outputs only for the current token. In both blocks, self-attention still reads all history K/V and cross-attention reads all reference motion K/V, so neither accessible window is shortened.

Training Performance Optimization: Fused RoPE and Short-Sequence Attention

Using PyTorch Profiler, I identified two sources of GPU overhead during PPO training of the two-stream temporal Transformer: intermediate tensor reads and writes in the multi-step RoPE implementation, and general-purpose attention kernels poorly suited to the model's short sequences. I developed fused RoPE and specialized attention forward and backward kernels in Triton, matching the original backend's key floating-point operation order to address numerical differences that were amplified during full training updates.

In benchmarks using actual environment rollouts on an RTX PRO 6000 Blackwell, with the model architecture, precision settings, and PPO configuration unchanged, PPO update time fell from 3.2139 s to 1.6718 s (48.0% lower), while combined rollout collection and update time fell from 4.5597 s to 2.9826 s (34.6% lower), yielding approximately 1.53× iteration throughput. These measurements exclude log writes, periodic evaluation, checkpoint saving, and state resets.

Performance Bottlenecks, Kernel Implementation, and Numerical Validation
Fuse RoPE to Reduce Intermediate GPU Memory Access

I fused feature pairing, sine/cosine multiplication, and rotation arithmetic into a Triton kernel, implemented a fused backward pass, and integrated both into the existing training pipeline through a custom torch.autograd.Function. Preserving the original FP32 operation order reduced repeated writes and reads of intermediate results. In an independent ablation, caching sine/cosine tables alone improved performance by only about 0.12%; kernel fusion provided the main speedup.

Tailor Attention Forward and Backward Passes to the Actual Short Sequences

The attention shapes across the two Fusion Blocks are 11×11, 11×21, 1×11, and 1×21, with a head dimension of 32. I used smaller tiles suited to these shapes and implemented Q/K/V gradients with support for the actual tensor layouts. In profiler comparisons using the same actual PPO minibatch, the total time of the main attention forward and backward kernels fell from 46.850 ms to 13.244 ms.

Go Beyond Mathematical Equivalence to Numerical Agreement During Training

The initial kernels were faster, but small local differences were amplified by subsequent TF32 linear layers, causing AdamW state validation to fail. I examined the original backend's FastF32 path and matched operand splitting and rounding, the sequence of three TF32 matrix multiply-accumulate operations, segmented reductions, and key operation ordering in the softmax forward and backward passes. The final implementation passed validation of complete training updates within the predefined error tolerances.

Validate with Actual Rollouts and a Complete PPO Update

Using 2048 environments, 24 rollout steps, and 5 epochs × 4 minibatches, I compared the baseline and optimized implementation from identical model and optimizer states on the same collected on-policy data. In the tested cases, the recorded maximum absolute differences were zero for full-model outputs and gradients, as well as 4 loss values, 129 parameters, and 387 AdamW state tensors after 20 optimizer steps. Adaptive learning-rate decisions also matched. An additional 48 tests covering tensor layouts, partial gradient computation, and repeated runs passed.

The performance results are steady-state measurements after warmup; the 20 optimizer steps above constitute one complete PPO update. Validation is limited to the tested hardware, FP32 with the original TF32 settings, and the specified short-sequence shapes. It does not establish identical long-term training trajectories or final convergence.

01 Skill-Level Data Augmentation for Robotic Manipulation Paper · Co-first Author · Accepted by Journal of Software Generate recovery and object-shape variation samples from just one human demonstration per task to improve manipulation success. View details

Research Question: How Can Robots Learn Recovery and Adapt to New Objects from Very Few Demonstrations?

Robot imitation learning relies on human demonstrations: observations and actions are recorded while a person controls the robot, then used to train a model to predict actions from observations. Collecting real demonstrations is expensive. With only successful examples, a model may fail to correct execution errors or generalize to objects with different shapes. This work generates additional training samples by editing existing demonstrations, a process known as data augmentation.

The paper divides manipulation trajectories into a motion-planning stage before contact and a skill-execution stage after contact, such as approaching a cup and then grasping it to pour. Skill-level augmentation generates samples for the latter stage and its initial states, focusing on recovery from deviations and observations of altered object shapes.

Method: Add Recovery Trajectories and Perturb Non-Contact Geometry

Failure-recovery augmentation edits point clouds (3D samples of object surfaces) and robot-arm states to simulate position errors, orientation errors, or visual occlusion at the start of object interaction. It then generates a trajectory back to the normal skill starting state and appends the original manipulation sequence. These samples teach the robot to recover from deviations and continue the task.

Contact-preserving perturbation keeps the geometry of the robot-object contact region intact while widening, stretching, or deforming other regions. For example, when the gripper holds a cup handle, the handle's contact geometry is preserved while the cup body changes shape. This increases shape diversity while retaining the contact relationships in the original demonstration.

Experiments and Results

Starting with one real demonstration per task, the experiments train DP3 policies on augmented data to predict actions from point clouds. Real wiping, pouring, and grasping tasks are evaluated on a Franka robot arm. Compared with augmentation that only changes object positions and approach paths, skill-level augmentation improves manipulation success and robustness to new objects and execution deviations.

In recovery experiments, the robot learns to correct abnormal states before continuing. When its own arm blocks the camera and hides the target, for example, it raises the arm to restore visibility before resuming the task. When the end effector drifts, it can also return to a state from which the task can continue. The videos below demonstrate these recovery behaviors on the real robot.

02 CLIP-Based Few-Shot Recognition for Robotic Perception via Multi-Scale Semantic Injection and Consistency Regularization Paper · Primary Contributor · Under Review Combine features from multiple visual layers with class-text guidance for classification from very few labeled examples. View details

Motivation: Different CLIP Layers Retain Different Information

CLIP learns from paired images and text to map visual content and language concepts into a shared feature space. Its visual encoder processes images layer by layer: early and intermediate layers retain more local structure, shape, and spatial information, while deeper layers emphasize category semantics with progressively coarser spatial detail. Many CLIP-based few-shot classifiers use only the final layer and may therefore miss local details needed to distinguish similar categories.

The figure compares attention responses at different network depths for four types of images. Earlier layers focus on the objects themselves, including screws, hammers, irons, and moka pots, preserving their locations and outlines. Deeper responses are more dispersed, with some attention falling on the background or unrelated regions. This suggests that features at different depths are complementary: classification benefits from both intermediate local evidence and deeper semantic information.

Method: Guide Feature Extraction with Class Text and Fuse Multiple Visual Layers

Multi-Scale Semantic Injection (MSI) selects outputs from several intermediate layers of a frozen CLIP visual encoder. At each layer, class names are encoded by CLIP's text encoder. Text tokens and image patch tokens then pass through a shared Transformer, providing class-level guidance for the visual features.

After semantic injection, a global token containing class information acts as a query in cross-attention to select the most relevant local patches and produce a representation for each layer. Attention pooling then learns how to weight the layers, combining local spatial details with deeper semantics. Few-shot classification uses the distance between this representation and each class prototype.

During training, labeled support images can use their true class names, but query images have no known labels. Direct reliance on text can therefore create a mismatch between their features. Semantic Consistency Regularization (SCR) processes the same image with and without text prompts. It randomly disables some prompts so the model adapts to both inputs, while explicitly keeping the two feature representations close. This allows training to benefit from text while maintaining stable behavior with image-only inputs.

Experiments and Figure Analysis

Experiments use MiniImageNet, TieredImageNet, and CUB under 5-way 1-shot and 5-way 5-shot settings: each classification episode has five classes with one or five labeled examples per class. Comparisons with existing few-shot learning and CLIP adaptation methods show competitive accuracy on both general-category and fine-grained datasets.

The left side of the figure shows attention maps from CLIP layers 6, 8, 10, and 12 with the text prompt “keyboard.” Layers 6 and 8 have more dispersed responses, layer 10 focuses more clearly on the keyboard, and layer 12 captures more abstract category information. The heatmap on the right shows how 16 attention heads weight the four layers. Most heads combine multiple levels and assign higher weights to layers 10 and 12, indicating that aggregation selects complementary information across depths.

Ablations remove multi-layer features, cross-attention, random semantic injection, and the feature-consistency loss. Classification is strongest when multi-layer features and cross-attention are both enabled. Randomly disabling text prompts together with explicit feature alignment also outperforms configurations that omit either component. MSI primarily improves extraction of local discriminative evidence, while SCR reduces the mismatch between text-assisted support images and image-only queries.

03 Long-Range 3D Target Localization and Aiming Control RoboMaster 2026 Fuse camera and LiDAR measurements for target localization, then refine aiming with impact feedback and attitude compensation on a real robot. View details

Problem: Monocular Localization Is Insufficient Beyond 20 m

This project supports long-range lob shots in the RoboMaster robot competition. Beyond 20 m, targets occupy few image pixels, and distance amplifies corner-detection errors in PnP-based monocular localization. The resulting depth errors can exceed the accuracy required for ballistic calculations. I introduced LiDAR, jointly calibrated it with the camera, and used point clouds for more accurate target range and 3D position estimates before computing trajectories and gimbal commands.

Sensing Hardware

Method: Camera–LiDAR Localization and Feedback-Based Aiming Corrections

ROS2_CALIB first estimates the relative position and orientation of the camera and Livox Mid-70 LiDAR. At runtime, YOLO target boxes are associated with the corresponding LiDAR points. Clustering and filtering reject outliers, and the remaining points estimate horizontal range, vertical offset, and 3D target position. Ballistic calculations then determine the required pitch and yaw offsets and generate commands for the two-axis gimbal.

To handle false and missed projectile detections, single-object tracking associates the same projectile across frames. Its observed trajectory and impact location guide aim corrections. When the chassis tilts, IMU attitude measurements and two-axis gimbal kinematics transform coordinates so that yaw and pitch commands remain referenced to the ground.

Results: Integrated Localization, Feedback, and Attitude Compensation

The system has completed integration and real-robot testing of sensor calibration, 3D localization, gimbal control, projectile tracking, and attitude compensation. An independent laser rangefinder provided reference distances to check the localization results. The video below shows the sensing and control process on the robot.

04 Low-Bandwidth Image Transmission with Neural Compression RoboMaster 2026 Compress 192 × 192 images to at most 560 B per frame, with accelerated inference and super-resolution reconstruction for impact observation. View details

Problem: Enforce a Strict Frame Budget with Limited Compute and Battery Power

The communication protocol allows only about 560 B of image data per frame; oversized frames cannot be sent directly. CompressAI's pretrained mbt2018_mean model uses a fixed compression configuration, lacks real-time variable-rate control, and cannot strictly guarantee that scenes of different complexity fit the budget. I added QVRF-based rate adjustment and retries for oversized frames so the bitstream can adapt to scene complexity.

Compute and power are also constrained. The onboard sender runs on a NUC12, while the receiver is a laptop with an NVIDIA GPU operating on battery power. Both ends must continuously perform neural inference, entropy coding, and image processing, making inference efficiency and runtime overhead important alongside rate control.

Compression: Control Frame Size Through Feature Quantization and Feedback

Image features and statistics. The sender feeds a 192 × 192 RGB image into the analysis network ga to obtain a compact reconstruction feature y. Floating-point features are still too large to transmit directly, so they require quantization and entropy coding. The hyperprior network ha transforms y into a compact auxiliary feature z. After z is quantized and decoded, hs predicts the mean and scale of each element in y, providing a probability model for coding.

Quantization and entropy coding. The predicted mean is subtracted from y, the result is multiplied by a gain factor, and values are rounded to integer symbols. A smaller gain groups more nearby values into the same symbol, reducing byte count at the cost of image detail. Predicted scales select probability tables, and rANS entropy coding turns the symbols into a compact bitstream, assigning fewer bits to frequent symbols. The transmitted data includes the main y stream, the auxiliary z stream, and decoding information such as gain.

Per-frame feedback and oversized-frame handling. The next frame's gain is adjusted using the previous frame's byte count relative to the 560 B budget. Spare capacity increases gain to retain detail; a near-full budget decreases it. If a frame exceeds the budget, gain is reduced further and encoding is retried. If it remains oversized after repeated attempts, an OVER marker is sent and the receiver keeps the previous frame, preventing oversized image data from entering the link.

Receiver reconstruction. The receiver decodes z and uses hs to recover the same means and scales as the sender. It decodes the integer symbols of y with matching probability tables, divides by gain, and adds the means back. The reconstructed features pass through the synthesis network gs, followed by RLFN ×2 super-resolution. The auxiliary feature z lets both ends reconstruct the same statistics without transmitting large mean and scale arrays. Details of compression, rate feedback, and exception handling are available in the technical documentation ↗.

Inference Optimization: Reduce Overhead Along Both Data Paths

The sender uses the NUC12 integrated GPU and OpenVINO to accelerate ga. PrePostProcessor folds BGR uint8 input handling, resizing, RGB conversion, and normalization into the inference graph, avoiding separate CPU preprocessing. NumPy searchsorted replaces CompressAI's original build_indexes search to reduce probability-table index construction overhead before entropy coding.

The receiver fuses the synthesis network gs and RLFN ×2 into a single TensorRT engine, producing 384 × 384 images without returning intermediate features to the CPU. CuPy then converts NCHW FP32 output to HWC uint8 on the GPU. Entropy-coding modules remain on the CPU because cross-device numerical differences could produce inconsistent probability tables at the two ends.

Results: Real-Time Low-Bandwidth Transmission for Impact Observation

The system keeps compressed 192 × 192 RGB images within 560 B per frame. The implementation documented in the repository supports 24 FPS transmission and reconstructs 384 × 384 images at the receiver. Real-world tests show that the reconstructed view can help identify projectile impacts and correct aiming.

The bottom-right view in the video below is the final display seen by the operator. It shows the scene after compression, transmission, decoding, and super-resolution reconstruction, supporting observation of targets and projectile impacts.

05 YOLO-Based Detection and Real-Time Auto-Aiming RoboMaster 2025 Train and deploy detection models on Orin NX, then increase measured throughput from 90 to 150 FPS with a multithreaded pipeline. View details

Power Rune Detection and Model Deployment

I handled image collection, cleaning, annotation, YOLO training, and TensorRT deployment for the Power Rune, a rotating target in the competition, running detection on NVIDIA Orin NX. When a rule change removed the target's outer frame, I used its known dimensions and OpenCV to mask the frame in existing images. This reduced the mismatch between training data and the new field appearance, allowed the dataset to be reused, and supported deployment of the updated model in competition.

Multithreaded Pipeline Optimization for Auto-Aiming

Image capture, preprocessing, inference, postprocessing, Kalman-filter observation updates, gimbal control, and firing control run in separate task threads. Data moves through a producer–consumer pipeline, with condition variables synchronizing threads when data becomes ready. This reduces blocking between stages. Multiple inference threads address the inference bottleneck and allow processing of different frames to overlap.

Under the project's test conditions, multithreading increased processing throughput from 90 to 150 frames per second. The two videos below show the auto-aiming system running on real robots.

06 Mobile Robot Chassis Control and Power Limiting RoboMaster 2024 Build a modular controller for two omnidirectional chassis types and fit a power model from real-vehicle data to dynamically limit motor output. View details

Embedded Chassis Control Framework

I developed an embedded control framework for omni-wheel and mecanum-wheel chassis, separating peripheral communication, state observation, and control logic into independent modules. This reduces coupling between control algorithms and hardware communication. Communication adapters, state observers, and control parameters can be modified independently, simplifying reuse and further development across chassis types.

Motor Power Modeling

I collected motor speed, current, and power measurements from real vehicles at different speeds and loads to fit a motor power estimation model. At runtime, the controller estimates total chassis power from each motor's state and dynamically limits motor targets. This adapts power control to current operating conditions instead of imposing a fixed output cap.
